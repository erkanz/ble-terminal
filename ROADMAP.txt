5. NON-NEGOTIABLE BLE / GATT BASELINE
======================================================================

GENERIC BLE UART
- Auto Detect must remain supported.
- Nordic UART Service must remain supported.
- HM-10 FFE0/FFE1 must remain supported.
- generic UART-style GATT must remain supported.
- manual Custom UUID mode must remain supported.

RT-950 QUALIFIED PROFILE
- service FFE0
- write FFE1
- notify FFE1
- write and notify may be the same characteristic
- profile RADTEL_RT950_KISS only when device/signature detection matches
- ordinary HM-10 must not be labeled RT-950 solely because it uses FFE0/FFE1

Qualified readiness chain:
    BLE CONNECTED
    -> SERVICES DISCOVERED
    -> FFE1 FOUND
    -> FFE1 VALUECHANGED HANDLER ATTACHED
    -> FFE1 CCCD WRITE RESULT=Success
    -> FFE1 NOTIFY ACTIVE
    -> RADTEL KISS READY
    -> RAW BLE NOTIFICATION

GATT OWNERSHIP / CACHE
- Auto Detect retains the selected GattDeviceService.
- It retains write and notify characteristics.
- It retains the full selected-service characteristic list.
- wrappers are connection-scoped only.
- reconnect creates fresh wrappers.
- Inspector reuses qualified cached Auto Detect objects when applicable.
- Inspector must not perform a second FFE0 characteristic enumeration merely to redraw
  a cached RT-950 tree.
- Inspector must not dispose Auto Detect-owned live objects.
- duplicate/non-owned wrappers may be disposed safely.

CCCD / NOTIFY
- attach ValueChanged before enabling CCCD.
- avoid duplicate handler attachment.
- use result-bearing CCCD API.
- log real GattCommunicationStatus / protocol error where available.
- only Success marks notify active.
- active cached FFE1 subscription should be reused instead of blindly rewritten.

GATT SERIALIZATION
- main terminal and Inspector share the main _gattOperationGate.
- manual main TX is serialized through its TX queue/gate.
- KISS TCP bridge TX uses the main GATT serialization gate.
- Phase H compare sessions each own an independent GATT serialization gate and TX gate.
- notification callbacks must not block on a global shared gate.
- stale route/wrapper identity must be revalidated after waiting for a gate.

RAW / PROTOCOL
- raw BLE notification evidence must remain visible before higher-layer parsing.
- layered decode is additive:
      RAW BLE -> KISS -> AX.25 -> APRS
- a higher-layer decode failure must never erase lower-layer raw evidence.
- KISS state must survive BLE notification fragmentation.
- repeated FEND and FESC/TFEND/TFESC remain supported.
- malformed/non-KISS bytes remain observable.
- TCP packet boundaries are never treated as KISS frame boundaries.

UI BASELINE
- dark mode and dark scrollbars
- configurable terminal foreground/background
- File / View / Settings / About menus
- LF default line ending
- Local Echo default OFF
- Enter-to-send
- decoded AX.25/APRS details stay in dedicated decoded view rather than flooding serial output
