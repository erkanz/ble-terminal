BLE SERIAL TERMINAL - PHASE F GATT SNAPSHOT / COMPARE TEST CHECKLIST
===================================================================
Date created: 2026-09-06
Scope: BLE Serial Terminal Phase F
Firmware changes: NONE
Radio firmware changes: NONE

PURPOSE
-------
Verify deterministic capture/export/import/compare of GATT database/state while preserving the qualified RT-950 Auto Detect cache/FFE1 notification path.

ENTRY POINT
-----------
1. Connect to a BLE device.
2. Open GATT Inspector.
3. Click "Snapshot / Compare" in the Inspector toolbar.

Snapshot capture refreshes the existing Inspector discovery path first. For the active Auto Detect service it reuses the existing cached service/characteristic objects; it does not intentionally issue a second FFE0 GetCharacteristicsAsync on the RT-950 cache-owned service and it does not write characteristic values.

A. BASIC SNAPSHOT CAPTURE
-------------------------
[ ] Connect RT-950 and reach RADTEL KISS READY.
[ ] Open GATT Inspector.
[ ] Confirm FFE0/FFE1 appear normally.
[ ] Click Snapshot / Compare.
[ ] Capture Snapshot A.
[ ] Snapshot A header shows device, address, timestamp, service count and characteristic count.
[ ] Snapshot capture completes without disconnecting the radio.
[ ] Normal FFE1 KISS/APRS RX still works after capture.

A RESULT: PASS / FAIL


B. SNAPSHOT CONTENT
-------------------
Export Snapshot A as TXT and JSON.

Verify the snapshot contains:
[ ] format/version
[ ] capture timestamp
[ ] device name/address/connection state
[ ] GATT state / service discovery evidence
[ ] Auto Detect profile
[ ] Auto Detect service/write/notify mapping
[ ] current manual service/write/notify route separately
[ ] manual write type
[ ] manual override flag
[ ] services with short/full UUIDs
[ ] characteristics with short/full UUIDs
[ ] characteristic property flags
[ ] source/reused/ownership metadata
[ ] advertised Read/Write/WriteWithoutResponse/Notify/Indicate state
[ ] CCCD-known-active state where known
[ ] descriptors including 2902 when enumerated
[ ] discovery/access evidence from Inspector diagnostics

For RT-950 verify FFE0 and, when exposed by the radio, FFE1 / FF31 / FF32 details are retained.

B RESULT: PASS / FAIL


C. AUTO BASELINE VS MANUAL ROUTE
--------------------------------
With RT-950 connected:
[ ] Capture A with normal Auto Detect route (FFE0 / FFE1 write / FFE1 notify).
[ ] Change only the manual TX route to FF31 using RT950 OEM TEST, without sending.
[ ] Capture B.
[ ] Compare A -> B.
[ ] Auto Detect baseline mapping remains unchanged.
[ ] Manual Route / Write changes FFE1 -> FF31.
[ ] Manual OverrideActive changes False -> True.
[ ] No automatic TX occurs while changing route or capturing snapshots.

C RESULT: PASS / FAIL


D. IDENTICAL SNAPSHOT TEST
--------------------------
Without changing device/settings:
[ ] Capture A.
[ ] Capture B immediately afterward.
[ ] Compare A -> B.
[ ] No deterministic database/property/mapping differences are reported unless Windows discovery/access state genuinely changed.
